- **Inviting audience members to WeChat/AirDrop their own CSV on stage as a main-path beat — P3** — Today 3 of 4 metrics go null and apply crashes on foreign CSVs; even after the M generalization slice, real personal data landing in .data/runs, 300-column files, semicolon delimiters, and a boring dataset are all plausible. - **Editing one cell in the column browser live to 'introduce a variant' — P3** — It is manufacturing a finding in front of engineers, which is precisely the 演示味 the owner is trying to shed.
- **Visible model fallback selector (claude-sonnet) and any Haiku/Sonnet comparison — P3** — One model, one prompt_version, on screen. A selector invites 'so which one did you tune for' and looks like a chatbot.
- **Turning Wi-Fi off physically as the fail-closed demonstration — P2, P3** — If the laptop is tethered to a phone hotspot, toggling Wi-Fi mid-demo can strand the browser tab or the terminal; use the deterministic red-team 'timeout' case and describe the network scenario verbally.
- **In-browser 现场重算 of every chain node from displayed canonical JSON — P2** — canonical_json uses ensure_ascii=False, sort_keys, compact separators and round(…, 8) float normalization; one mismatch on a projector reads as 'the hashes don't match'. Restrict browser recomputation to raw release.csv bytes; let the server /verify recompute JSON hashes.
- **Terminal `echo x >> source.csv` as the primary tamper beat — P1** — Great encore, bad main path: forgetting `mv source.csv.bak source.csv` kills the rest of the run. The in-memory tamper-test button gives the same red row with zero recovery risk.
- **Accepting the model mapping only when it equals the policy glossary mapping — P1** — It makes the live Claude call decorative; a sharp engineer will open policy.yaml, see the aliases, and conclude the AI does nothing. The honest fix is the opposite: include non-glossary variants in candidate_counts and let a grounded, human-approved model mapping become the action (targets still vocabulary-closed).
- **Full cell-level change ledger hashed into the manifest with a new reconciliation validation, audit.jsonl timeline, SSE events, and the determinism replay strip all in the same day — P1, P2** — Each is defensible, but together with the console rebuild they exceed the budget and each touches execute()/manifest/golden, which is the serialization point across parallel agents. - **40ms staggered reveal on the gate checklist — P2** — Harmless in isolation but it is exactly the animation smell the redesign is removing; render instantly.
- **Projector mode toggle, dark mode, charts/dashboards, auth, docker/cloud changes, Polars lazy rewrite, manifest signatures/PKI — various** — None advance 含金量/AI 赋能/AI 监管; browser zoom at 125% covers legibility; recomputable sha256 is more honest than a key held on the same laptop.
- **Quoting invented per-beat numbers (73, 312, 316 for SEM-004; '~420/412/480 bytes'; '2.8s') in the script — P2, P3, P4** — SEM-004 is 183 records; byte counts and latencies must be read from the screen live, never memorized. ## Gaps all missed
- The AI call is currently a glossary rubber stamp and no proposal fully fixes it: engine.py builds observed_counts only from aliases already listed in policy.canonical, and prepare_dry_run builds NormalizeCategoryAction from finding.details['mapping'], never from the model. For AI 赋能 to be honest the fixture needs 2–3 non-glossary variants (e.g. 'high blood pressure', 'HBP', '高血压') so the model performs actual semantic judgment, and prepare_dry_run must use the persisted grounded proposal mapping (sources ⊆ observed candidates, targets ⊆ vocabulary) when the human outcome is APPROVE_PROPOSAL, falling back to the glossary mapping when no assessment exists. This is one golden regeneration and roughly M effort, and without it the whole AI beat is inspectable as theater.
- Nobody said to verify the model identifier and structured-output parameter names against the current SDK/docs before building. A live HTTP 400 'model not found' or 'unknown parameter output_config' in front of engineers is fatal; the first task of the semantic-endpoint agent should be a one-line smoke call with the exact model id and format, logged with its response id.
- No proposal produced a parallelization plan with the serialization points named. RunReport/DryRunReport/ReleaseManifest schema additions, fixture changes, and golden regeneration are all shared state; four agents editing engine.py/governance.py/models.py concurrently will spend the day resolving conflicts. Assign one agent ownership of contracts + golden, land additive schema fields first, then let the semantic, console, and tamper/verify agents build against the frozen schema.
- No proposal set a hard cut line by time of day. A realistic day: by noon the semantic endpoint (two-step), red-team harness, tamper-test, persistence, timings, and the console skeleton must be green in tests; the engine generalization and second dataset are attempted only by a dedicated agent and are dropped at 16:00 if the golden test is not green, with the BYO invitation removed from the script accordingly.
- There is no run-list endpoint; every IA assumes one. GET /v1/runs (scan .data/runs/*/report.json) is S and needed for the console home and 重置演示.
- No middle-tier fallback between 'live laptop' and 'public replay site': a screen recording of one full live pass (with the real Opus call and its latency) should be on the laptop and the phone. If the API process dies, playing the recording is more honest than pretending the replay is live, and faster than a restart.
- The persisted red-team and semantic results become part of the run directory, but no proposal specified that red-team outputs must be stored outside the run's decision state (e.g. .data/runs/<id>/redteam/) and excluded from /verify so a simulated tamper cannot be mistaken for provenance later.
- Chinese-first means the t(en, zh) helper should be read as zh-first in the new console strings and Chinese finding titles must come from a finding_type/signal dictionary (or the engine) so the second dataset and adversarial fixture need no frontend edits; nobody addressed that canonical_json's ensure_ascii=False makes Chinese tokens count as multi-byte in the displayed byte count, which is fine but should be stated as UTF-8 bytes on screen.
- Nobody proposed a five-line 'what to say when asked about scale' card: P0 bounds are explicit (25 MiB / 250k rows / 200 columns), detectors run as Python loops over frame.to_dicts(), the timings are shown live, and the next step is Polars expressions. Rehearsed honesty on the weakest point earns more than any feature.
- The apply idempotency key is carried in the request body while CORS allows an Idempotency-Key header; harmless, but an engineer reading the API log will notice the mismatch. Pick one (header is conventional) and show it in the API drawer.
